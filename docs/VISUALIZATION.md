# XRAGOS 测试工作流可视化

面板直接读取 Group / Task 的真实报告、事件、模型调用记录、修订与快照。查看与运行实验彼此独立：刷新页面只读取文件，不发起模型请求。

## 启动

在仓库根目录运行：

```bash
python -B -m visualization --runtime-root ../Preparation/runtime --port 8765
```

打开 <http://127.0.0.1:8765>。默认路径为仓库同级的 `Preparation/runtime`；`--runtime-root` 也可指向其他实验产物父目录。使用可编辑安装后，`ragskill-visualize` 与模块入口相同。

服务仅监听本机回环地址。退出终端进程即可停止服务；页面默认手动刷新，不创建周期巡检。

运行状态来自持久化日志，面板不核对后台进程存活。没有终态记录的运行显示“日志未结束”；中断留下的旧开始事件不能证明进程仍在运行。

## 阅读一次运行

1. 在左侧选择实验，查看实际 Group、模型、完成范围与状态。
2. 选择 Task，沿流程图查看共享规划、QA 执行、评估、自优化和继承。正常拒绝、跳过、执行失败与进行中状态分别保留。
3. 点击 Manage、Agentic、Component，查看各阶段的输入、模型 prompt、回答与共享方案。每 Task 的三阶段规划与每 QA 的执行分开展示。
4. 在 QA 列表中选择问题，查看预测、指标、轨迹、组件执行耗时与该问题的模型调用。点击组件耗时，可展开该组件每次真实函数调用的输入、输出和源码；其模型请求按组件调用 ID 关联。同一组件多次迭代时，可以分别选择每次调用。
5. 点击 Policy 选择或修改，切换查看初始提案和格式修复请求。一次逻辑优化可能包含多个模型请求，HTTP 重试另计。
6. 查看验证结果、文件差异与 Skill 哈希链，核对下一 Task 是否从接受后的版本重新规划、加载并执行。执行验证的重跑不计入主 QA 数量。

详情中的源码来自运行的冻结快照；若只能提供当前仓库参考代码，会明确标明其来源，不能用它证明历史运行版本。修改被接受仅表示通过该运行声明的接纳检查，不能单独证明指标提升。

## 数据完整性与边界

标准 Task 工作流会记录模型输入输出到运行目录中的 `model-captures/`；可以通过 `--no-capture-model-io` 关闭新增模型输入输出采集。该开关不改变模型调用、优化与验证逻辑。快照、调用记录和界面都不会保存或展示 settings 凭据。

| 记录 | 内容 |
|---|---|
| `capture-log.jsonl`、`captures/` | 真实 generate 的开始与终态、完整脱敏 prompt/回答、实际可用的请求统计 |
| `component-calls.jsonl`、`components/` | 组件函数调用的输入、输出、状态及其模型调用 ID |
| `compile-captures.jsonl`、`executed-sources/` | 编译加载与组件实际调用的源码路径、SHA 和快照 |
| `manifest.json`、`source-code/`、`source-skills/` | 源码基线、采集范围、脱敏标记及观察器警告 |

组件的大型 Corpus 输入使用带数量、来源指纹和省略说明的摘要，避免为每题复制整份语料；普通检索结果保留文档正文。任何捕获上限与省略都会明确记录。模型 prompt 与回答使用独立文本捕获，不套用 Corpus 摘要。采集故障会写警告，不改变模型返回值、异常或重试策略。

模型输入输出可能包含测试问题、检索证据和业务文本，应与对应实验产物一起保存在受控本地目录。面板不提供任意文件浏览、settings 读取、代码执行、修改或部署接口。

旧批次可能只有 Policy 提案审计，没有 Executor 完整 prompt；旧 HTTP 统计字段也可能缺失。面板保留“未记录 / 部分覆盖”的状态，不从回答推测 prompt，不把未知尝试数填成零。中途正在追加的 JSONL 不完整末行不会当作一次完整成功或失败。

如果旧批次仅记录 QA 级模型调用，没有逐组件关联，点击 Critic 或生成器时不会把其他组件的调用冒充其专属 prompt。可返回整个 QA 手动查看这些原始调用。

模型请求失败与后续恢复保留各自记录；正在等待响应的请求不等于失败。报告中的主 QA、操作验证 QA、逻辑优化轮次、Policy generate 和 HTTP 尝试用于回答不同问题，应分别阅读。
