# Field-aware BM25F design

## Goal

Upgrade `component-bm25-retriever` from a single combined-length BM25 score to
field-aware BM25F while preserving the existing `run(inputs, context)` contract.
The component remains a lexical retriever and does not select, fuse, rerank, or
generate.

## Scoring

Tokenize `title` and `text` independently. For each query term, normalize its
frequency inside each field using that field's own document length and average
field length:

```text
normalized_tf(term, document) =
    body_tf / (1 - body_b + body_b * body_length / average_body_length)
  + title_boost * title_tf
      / (1 - title_b + title_b * title_length / average_title_length)
```

Apply the BM25 saturation once after the normalized field frequencies are
combined:

```text
score_term = idf * normalized_tf * (k1 + 1) / (normalized_tf + k1)
```

Document frequency counts a document once when the term occurs in either
field. Query terms remain deduplicated, and equal scores remain ordered by
document ID.

## Compatibility

The required input and output remain unchanged:

- input: `query`, `documents`, `top_k`
- output: `{"documents": [...]}` with a `score` on each returned document

Existing optional parameters keep their meaning:

- `k1`: global term-frequency saturation
- `b`: body length normalization
- `title_boost`: title field weight

Add optional `title_b`, defaulting to `b`, to allow independent title length
normalization without forcing callers to configure another parameter.

## Edge cases

- Skip an empty field contribution instead of dividing by a zero average.
- Continue returning no documents for an empty query, empty candidates, or a
  non-positive `top_k`.
- Reject non-finite or out-of-range `k1`, `b`, `title_b`, and `title_boost`.

## Verification

Add tests proving that:

1. irrelevant body length no longer dilutes a title-only match;
2. title boosting still ranks a title match above an equivalent body match;
3. `title_b` is validated;
4. existing normalization, duplicate-query, and empty-input behavior remains
   compatible.
